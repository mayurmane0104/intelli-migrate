# Workflow: Publish Assets

Anypoint Exchange provides the ability to publish assets in private Exchange instances and Exchange public portals. Publishing is the process of creating assets and making them available to consumers for discovery and reuse.

- 
[Creating an Asset](to-create-an-asset)- Create new assets in Exchange.
- 
[Editing an Asset](to-describe-an-asset)- Add a description, additional pages, terms and conditions, and tags, and change versions.
- 
[Managing Asset Lifecycle States](lifecycle)- Manage the promotion path of an asset’s lifecycle state.
- 
[Manage Versions](manage-versions)- View the version details of an asset, add a version for an asset, change the lifecycle state of a version, and delete a version.
- 
[Managing Asset Portal Resources](to-manage-asset-portal-resources)- List, retrieve, and delete resources from an asset portal with Exchange Experience API.
- 
[Simulating Data in REST APIs](ex2-to-simulate-api-data)- Use the mocking service to test OAS or RAML REST APIs with simulated data.
- 
[Downloading an Asset](to-download-an-asset)- Copy the asset to your computer.
- 
[Managing Categories](to-manage-categories)- Organize assets into categories.
- 
[Managing Custom Fields](to-manage-custom-fields)- Exchange administrators and organization owners can create custom fields to extend the Exchange asset metadata model and add custom data to any type of asset.
- 
[Deleting an Asset](to-delete-asset)- Remove an asset.
- 
[Changing the Version of an API Asset](to-change-raml-version)- Update the version of a RAML asset.
- 
[Publishing an HTTP API Asset](publish-an-http-api)- If you use Private Exchange, use the HTTP API to specify a placeholder for an endpoint.
- 
[Adding Policy Implementation Files to Published Policy Definition](add-policy-implementation-files-to-published-policy-definition)- If you published a policy definition, add the implementation files to make policy available at runtime.
- 
[FAQ](exchange2-faq)- Frequently Asked Questions.
